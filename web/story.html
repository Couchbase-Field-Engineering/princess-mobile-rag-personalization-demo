Chapter 1 · The question costs money

Every guest question has a price - a person, a phone line, or a model call.

Live chat keeps business hours and a queue. An AI concierge is always on - but the simplest build pays the LLM full price for every question, including the ones it answered a minute ago.

Chapter 2 · Where the LLM bill comes from

Four things make a chatbot expensive. Each one has a fix.

A model call is priced per token, in and out. The cost of a concierge is the number of calls times the size of each prompt - so the savings are in making fewer calls and smaller ones.

1

Repeat questions

Policy and product questions are the same for every guest: packages, check-in, Wi-Fi, dining times. Generating each one again is pure waste.

calls × guests
2

Context rebuilt every turn

A personal answer needs the guest's profile, the relevant policy, live inventory and prices. Rebuilding and re-sending that for every question is the largest prompt in the app.

tokens per call
3

Ungrounded, unscoped retrieval

Searching the whole knowledge store stuffs the prompt with chunks that aren't about this guest - more tokens, worse answers, and a privacy risk.

tokens per call
4

No answer offline

Every question that can't be answered at sea becomes a call-center minute later, or a lost booking.

the hidden cost

LLM Cache

The second guest to ask a playbook question gets the first guest's answer: an exact or semantic hit, zero tokens. Playbook answers hold no personal data, so sharing them is safe.

Couchbase LLM Cache

Context Cache

The context assembled for a guest and topic is cached in Couchbase with a key of guest, intent, export date and profile revision. Follow-up questions reuse it; a new export or a booking invalidates it.

Couchbase Context Cache

Scoped RAG application

The concierge is a registered RAG app scoped to today's playbook, and personal retrieval is filtered to this guest's own profile document. Small prompts, grounded answers.

Couchbase Knowledge Bases for RAG Chatbots

Answers on the phone

The cached context is also a Couchbase document that syncs to the guest's device, so the concierge answers at sea from Couchbase Lite - no call, no cost.

Chapter 4 · The same questions, two bills

Five questions: three model calls instead of five, and an answer at sea.

The same guests ask the same things of two concierges: one that runs through the Agent Operations Manager with its context on the phone, and one that calls the model every time.

1

Olivia: "What's included in Princess Premier?"

A playbook question. AOM: the RAG app retrieves the scoped playbook, generates once, and caches the answer. Plain chatbot: generates.

2

Priya asks the same thing

AOM: LLM Cache exact hit - no tokens, no latency. Playbook answers carry no personal data, so sharing is safe. Plain chatbot: generates again.

3

Olivia: "Can we upgrade to a suite?"

A personal question. AOM: builds her context once (her KB profile, the playbook, live upgrade offers), stores it in the Context Cache and in Couchbase, then generates. Plain chatbot: rebuilds the whole prompt and generates.

4

Olivia: "What would the Premium Suite cost?"

AOM: Context Cache hit - a short call on the cached context, with memory of the earlier turn. Plain chatbot: the full prompt again, plus the history.

5

At sea, no signal: "Remind me about the upgrade"

AOM: the cached context already synced to her phone; Couchbase Lite answers. Plain chatbot: can't reach the server.

Chapter 5 · One data plane for the AI

Build the context once. Reuse it everywhere - including the phone.

Personalization and the concierge run on the same Couchbase documents the phone syncs, so an answer paid for once in the cloud is reused by the next guest, the next question, and the same guest with no signal.

Adobe Real-Time CDP

Every morning the dataset export lands: one unified guest profile per row with loyalty, preferences, audiences and Customer AI scores. During the day the Profile Access API supplies the current audiences when a context is built. The playbook comes from AEM content fragments.

A five-minute script

  1. Pay once. Sign in as Olivia and ask "What's included in Princess Premier?" The chips show LLM cache · miss: the RAG app generated it from the scoped playbook.
  2. Share it. Sign in as Priya and ask the same thing: LLM cache · exact hit. Reword it: a semantic hit. Open AOM's RAG Applications page - the hit is counted against the app.
  3. Build context once. As Olivia: "Can we upgrade to a suite?" shows Context cache · built. Ask what the Premium Suite would cost: Context cache · hit. Open sources: her own profile and the playbook, nothing else.
  4. Go to sea. Profile → "At sea - no signal". Ask about the upgrade again: Answered on device · Couchbase Lite. Place the Princess Upgrade bid; it shows "On device".
  5. Back aboard. Turn the signal on: the bid syncs and Confirm triggers the Princess Stateroom Upgrade Agent - a second AOM identity scoped to the upgrade tools. It recalls the guest's stateroom history from AOM Agent Memory, applies the upgrade as a governed tool call, and remembers the outcome, so the concierge's next answer about rooms costs nothing to look up. Open the trace in AOM: one generated answer where a plain chatbot would have made five.
